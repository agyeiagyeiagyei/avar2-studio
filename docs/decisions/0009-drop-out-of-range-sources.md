# 0009 — Out-of-range sources are dropped (Glyphs.app / fontmake semantics), not extrapolated

- **Status:** Accepted; today a static-demo action only
- **Date:** 2026-08-03 (`8a879e3`)
- **Area:** `wasm/fontc-web/src/lib.rs` (`clamp_out_of_range`), `frontend/src/static-api.js`

## Context

A source — a brace layer or master — can sit outside the axis box the
font declares (a "stranded" source). The three compilers disagree on what
that means: a divergence oracle established that **Glyphs.app and the
fontmake/varLib pipeline drop such sources, while fontc extrapolates
them**. The studio's own in-browser compile is fontc, so an uploaded
source rendered differently from what the designer's Glyphs export would
ship.

## Decision

The static demo offers **Drop out-of-range sources** (`clamp_out_of_range`
in the wasm crate), which makes the studio's font match Glyphs.app and
fontmake. Mechanically: the stranded tuples' packed deltas **and** their
peaks/bounds are zeroed (zero deltas make the tuple inert; zeroed
coordinates make the peak-reading coverage audit see the drop — zeroing a
*live* peak is the mangling case, measured once as a default advance of
166 → 2154), in-range intermediate bounds are clamped to ±1, and HVAR is
rebuilt from the remaining tuples. The default instance is untouched:
glyf and hmtx stay byte-identical (`tests/clamp_oracle.rs` asserts it,
plus an anti-mangling outline bound against the fontmake build — exact
equality is not provable, fontdrasil and fontTools tent shapes differ).
The drop sticks to the dataset (`clampOutOfRange` beside the corner
pins): rebuilds re-apply it and sessions carry it.

## Consequences

- The oracle used to compile the live `Crispy.glyphs` and went vacuous as
  that file stopped carrying stranded sources; it now uses
  `tests/fixtures/StrandedMini.glyphs` (CrispyMini plus two deliberately
  out-of-range braces, regenerated by `spike/make_stranded_fixture.py`).
- The Space tab that surfaced the action was removed on 2026-10-16
  (sprint T1.17); `clampOutOfRange` remains in the static provider and
  `coverage.js` stays because the provider uses it. The live-mode
  `pinCorner` / `clampOutOfRange` / `addMappingRow` API methods and their
  server routes are dead code awaiting removal.
- The desktop build never applies the drop — a `.glyphs` with stranded
  sources renders them extrapolated in the desktop preview.
